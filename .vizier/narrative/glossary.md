# Glossary

- Review bundle: The on-disk artifact directory for one `anne review` run at `.anne/reviews/<review-id>/`. Anne now publishes readable `comments.json` and `comments.md` before each advertised `manifest.json`, so every advertised snapshot is self-contained from the moment it becomes discoverable. Successful runs include the reviewed diff, manifest, rendered comments, structured findings, per-file patches, and raw agent I/O; preflight failure bundles are smaller and guarantee only `manifest.json`, `comments.md`, and `comments.json = []`. Newly written review manifests and review-id timestamp prefixes now always use canonical UTC `YYYY-MM-DDTHH:MM:SSZ`.
- Usable review bundle: For `anne address`, a review bundle whose advertised public snapshot is readable as a set: `manifest.json`, `diff.patch`, `comments.json`, and `comments.md`. Address scans candidates newest-first by canonical `generated_at` first and `review_id` second, prefers completed bundles over running bundles, treats missing or malformed timestamps as lower-confidence metadata than canonical UTC timestamps, skips unusable bundles, and still treats `manifest.status = failed` as eligible when that public snapshot is readable.
- Review materialization boundary: The point after repository discovery and config loading where Anne allocates `<review-id>`, creates `.anne/reviews/<review-id>/`, writes an initial manifest with `stage = preflight`, and begins repository-open/ref/merge-base/diff preflight inside that durable bundle.
- Review stage: The manifest field that marks the furthest persisted review phase Anne reached. `preflight` covers repository-open/ref/merge-base/diff setup, `file_review` covers per-file enumeration and agent execution, and `rendered` means the final review outputs were written.
- Preflight progress: The machine-readable manifest object that records whether Anne opened the repository and resolved the base ref, head ref, merge base, and full diff before the run terminated or advanced into file review.
- Review snapshot publication: Anne’s manifest-last publication rule for review bundles. Every coordinator-owned running or terminal snapshot writes `comments.json`, then `comments.md`, then `manifest.json`, so other commands never discover a newer manifest that points at missing comment artifacts.
- Canonical timestamp: Anne’s fixed-width UTC timestamp contract, `YYYY-MM-DDTHH:MM:SSZ`. Bytewise string order matches chronological order, newly written review/address manifests always use this shape, bundle-id prefixes derive from the same value with filesystem-safe `:` replacement, and epoch-clamp fallback serializes as `1970-01-01T00:00:00Z` instead of a `unix-*` sentinel.
- Address bundle: The on-disk artifact directory for one `anne address` run at `.anne/address/<address-id>/`, including the selected source comments, manifest, readable summary, per-comment agent I/O, and generated feature specs. Anne reserves the bundle root itself before writing run-specific files, so each invocation gets a distinct historical bundle even when the readable base id collides. Newly written address manifests and address-id timestamp prefixes use the same canonical UTC timestamp contract as review bundles.
- Address bundle reservation: The atomic directory-creation step that turns the readable base id `<timestamp>-latest-<selection-filter-slug>` into the final reserved `address_id`. Anne first tries the unsuffixed base path, then retries deterministic siblings with `-2`, `-3`, and so on on `AlreadyExists`, keeping `selection_filter` unchanged while isolating same-second runs across processes.
- Address spec validation: The lightweight acceptance gate Anne applies to the final assistant text for one address comment after any configured `progress_filter`: trim surrounding whitespace, reject empty output, reject output with no line whose first non-whitespace character is `#`, then normalize accepted specs by inserting `## Source Comment` when needed and ensuring a trailing newline.
- Merge-base review: Anne’s canonical review scope. The command resolves the merge base between `<base>` and `<head>` through `libgit2` and reviews the diff from that merge base to the head ref rather than accepting two-dot range math.
- Source comment: A persisted structured review finding from `comments.json` that `anne address` uses as the unit of planning work, including required `id`, `path`, `side`, `line`, `severity`, `title`, and `body` fields plus any recorded `hunk_header`, `patch_file`, or `confidence`; human-readable anchor text such as `new:6` is derived later from `side` and `line`.
- Synthetic review bundle fixture: The `tests/address.rs` helper that creates `.anne/reviews/<review-id>/` inputs for address integration tests. It accepts raw Rust strings in `ReviewCommentSpec`, JSON-escapes every string-valued field written into `comments.json`, preserves the fixture’s stable field order/pretty formatting, and immediately re-parses the generated JSON so malformed fixture text fails during bundle construction instead of later inside `anne address`.
- Canonical review patch: The per-path patch text Anne now constructs during diff generation and then reuses everywhere else. `diff.patch`, `files/*.patch`, prompt bodies, anchor parsing, manifest file records, and markdown rendering all derive from that same canonical patch string instead of rebuilding file sections later from a monolithic diff.
- Reviewable file: A changed path whose canonical review patch contains textual hunks and is not excluded by binary detection, rename-only detection, ignore prefixes, or the per-file patch size limit. Regular-file `<->` symlink conversions are reviewable when Anne can expand both payloads into textual delete/add hunks, while still staying one logical file record.
- Skipped file: A changed path that Anne records but does not send to the agent, along with an explicit reason such as `binary diff`, `pure rename without textual changes`, `metadata-only change without textual diff`, `binary file/symlink typechange`, or `ignored by review.ignore_prefixes`.
- Agent workers: The `[agent].workers` configuration value that bounds concurrent per-file review jobs and per-comment address jobs. Anne defaults it to `4`, and `1` disables parallel fan-out.
- Progress filter: An optional command configured under `[agent].progress_filter` that receives agent stdout on stdin and emits the final assistant text on stdout while using stderr for progress/logging. `review` uses that text as findings JSON; `address` uses it as markdown spec text. Its presence alone does not change `agent.output`; explicit output modes stay authoritative, and only an omitted output may resolve to bundled-default `wrapped-json` when Anne selected the bundled default agent. Explicit user-configured filters stay strict. Anne’s bundled default filter is separate runtime provenance: it is auto-selected only when the bundled default agent is in use without an explicit filter override, and it may be skipped in degraded mode when `jq` is absent.
- Fallback item summary: The bundled default filter’s generic summary for unrecognized wrapped-json `item.started` and `item.completed` events. It prefers collapsed `item.text`, then collapsed `item.message`, then collapsed `item.status`; that same derived summary feeds both stderr progress lines and stdout fallback state, while placeholder text like `<item.type> update` remains display-only.
- Turn failure summary: The bundled default filter’s first-class stderr rendering for wrapped-json `turn.failed` events. It prefers collapsed `error.message`, then top-level `message`, then `detail` or `path`, and falls back to `event: turn.failed`; this improves persisted failure diagnostics without changing stdout assistant-text precedence.
- Bundled default shim: Anne’s checked-in Bash wrapper at `examples/agents/default/agent.sh` used when no explicit agent command is configured for the normalized `default` label. It stages prompt stdin in a temporary file, logs only an empty-prompt marker or first-line preview on stderr, and forwards the exact staged bytes into `codex exec --json -` without trimming trailing newlines.
- Wrapped-json decoder fallback: Anne’s built-in recovery path for `agent.output = "wrapped-json"` when no progress-filter result is available. It scans the raw JSONL stdout artifact for the final `agent_message` event, uses that text as the assistant response, and fails explicitly if no recoverable final assistant message exists.
- Effective agent runtime: The persisted per-file/per-comment runtime record that captures what Anne actually used after bundled-default resolution and preflight: the resolved output mode from explicit-or-derived config, whether a bundled filter was requested, whether any progress filter ran, how Anne derived the assistant text, and why a bundled filter was skipped in degraded mode.
- Validated finding: A structured review comment whose `path`, `side`, and `line` match an actual changed line in the reviewed patch and therefore can be safely published into `comments.json` and `comments.md`.
- Running review placeholder comments: The readable `comments.json = []` snapshot Anne publishes while a review is still running and final stable `R###` identifiers have not been assigned yet. The companion `comments.md` is still a progress artifact with explicit running/queued/failed per-file state.
- Tracked Git CLI guard: The review test that enumerates tracked `src/**/*.rs`, tracked `tests/**/*.rs`, and tracked `*.sh` paths from the repository index, then fails on direct `Command::new("git")`-style Rust subprocess construction or direct shell `git` / `exec git` entrypoints.
- Native build contract: Anne’s checked-in default build story for Unix-like development and CI. The current contract is Rust `1.85+` plus a native C toolchain for vendored `libgit2`, with no default requirement for a system `git`, OpenSSL headers, libssh2 headers, or system `libgit2`; `BUILD.md` is the authoritative note and `ci.sh` is the matching verification entrypoint.
- Dependency-surface guard: The combination of `ci.sh` checks and review tests that shell out to `cargo tree` to keep Anne’s default `git2` graph local-only by rejecting `git2`'s default `https`/`ssh` transport features and rejecting reintroduced `openssl-sys` or `libssh2-sys` crates in the default dependency graph.
- Plan record: The durable summary JSON for one implementation plan at `.vizier/state/plans/<plan-id>.json`, carrying branch/summary/job linkage plus provenance for the originating operator spec. The persisted `summary` is a normalized single-line description derived from the saved implementation plan doc when available, with deterministic fallback to `Plan <slug>` when no meaningful prose can be extracted.
- Plan provenance: The `source` and optional `source_path` contract on a plan record. `source` classifies the operator spec as `file` or `inline`; `source_path` is the canonical repo-relative operator-spec path only for file-backed plans. Older records may omit `source_path`, in which case they remain readable as legacy incomplete provenance.
