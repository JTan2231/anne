# Running Snapshot

Narrative theme
- Anne is now a filesystem-native diff review and follow-up planning CLI. The `review` command compares branches with merge-base semantics and persists findings under `.anne/reviews/`, while `address` turns persisted review comments into durable feature-spec bundles under `.anne/address/`.

Code state (behaviors that matter)
- `anne review --base <base> --head <head>` and `anne review <base>...<head>` both normalize to triple-dot review semantics. The command resolves the merge base between the two refs through `git2`/`libgit2` and reviews the diff from that merge base to `<head>`.
- `anne address` selects the newest available review bundle at runtime from `.anne/reviews/`, preferring the newest recorded `generated_at` and falling back to lexicographic review-id order when timestamps are missing or tied. `anne address <comment-id>` scopes that same selected review bundle down to one comment.
- Each address run writes `.anne/address/<address-id>/manifest.json`, `summary.md`, `selected_comments.json`, per-comment prompt/response artifacts under `agent/`, and generated markdown specs under `specs/`. Empty review selections still produce a successful bundle with zero counts.
- Each review run writes `.anne/reviews/<review-id>/manifest.json`, `diff.patch`, `comments.md`, `comments.json`, per-file patch artifacts under `files/`, and raw prompt/response artifacts under `agent/`.
- Review units are individual changed text files processed serially. Binary diffs, pure rename-only changes, metadata-only changes, ignored prefixes from `.anne/config.toml`, and oversized per-file patches are skipped and recorded with explicit reasons.
- Address units are individual structured review comments processed serially. For each selected comment, Anne loads `INIT.md`, derives the current feature-spec heading shape from it, builds a prompt with the source-comment metadata plus review patch context, and validates only that the returned spec is a non-empty markdown document.
- Agent runtime configuration lives in `.anne/config.toml` under `[agent]` and `[review]`. The shared runtime writes the prompt to agent stdin, preserves raw agent stdout as an artifact even on agent or filter failure, and optionally pipes stdout through `progress_filter` to obtain the final assistant text for either review JSON findings or address markdown specs.
- Agent responses must be JSON arrays of findings with `path`, `side`, `line`, `severity`, `title`, and `body`. Anne validates every anchor against changed old/new lines before publishing findings.
- Findings themselves do not make the command fail in v1. Operational problems such as repository/ref resolution failures, agent failures, invalid JSON, or invalid anchors mark the run failed while preserving the bundle for audit/debugging.
- `address` fails before bundle creation when no review outputs exist, `INIT.md` is unreadable, or a requested comment id is unknown. After bundle creation, per-comment agent failures or unusable outputs are recorded in the manifest and summary while later comments continue to run; the command exits non-zero if any selected comment failed.
- Automated coverage exists for CLI parsing, hunk-anchor parsing, merge-base review behavior, plain-text agent execution, progress-filter execution with invalid-anchor failure handling, rename-only review skipping from real `git2` diff data, newest-review address selection, lexicographic fallback selection for address, empty address selections, partial-failure address artifact preservation, and a guard test that blocks reintroduced Git CLI subprocess usage in tracked code and scripts.
