# Running Snapshot

Narrative theme
- Anne is now a filesystem-native diff review and follow-up planning CLI. The `review` command compares branches with merge-base semantics and persists findings under `.anne/reviews/`, while `address` turns persisted review comments into durable feature-spec bundles under `.anne/address/`.

Code state (behaviors that matter)
- `anne review --base <base> --head <head>` and `anne review <base>...<head>` both normalize to triple-dot review semantics. The command resolves the merge base between the two refs through `git2`/`libgit2` and reviews the diff from that merge base to `<head>`.
- `anne address` selects the newest available review bundle at runtime from `.anne/reviews/`, preferring the newest recorded `generated_at` and falling back to lexicographic review-id order when timestamps are missing or tied. `anne address <comment-id>` scopes that same selected review bundle down to one comment.
- Each address run writes `.anne/address/<address-id>/manifest.json`, `summary.md`, `selected_comments.json`, per-comment prompt/response artifacts under `agent/`, and generated markdown specs under `specs/`. `selected_comments.json` stays a sorted copy of the selected raw review comment objects, while prompts, summaries, and generated specs render readable `<side>:<line>` anchors on demand instead of persisting a separate `anchor` field. Empty review selections still produce a successful bundle with zero counts, and non-empty selections keep manifest/summary ordering stable by comment id even when worker completion order differs.
- Each review run writes `.anne/reviews/<review-id>/manifest.json`, `diff.patch`, `comments.md`, `comments.json`, per-file patch artifacts under `files/`, and raw prompt/response artifacts under `agent/`. Final `comments.json` and `comments.md` are written only after all per-file results have been collected, globally sorted, and assigned deterministic `R001+` ids.
- Review units are individual changed text files dispatched through a shared bounded worker scheduler. Binary diffs, pure rename-only changes, metadata-only changes, ignored prefixes from `.anne/config.toml`, and oversized per-file patches are skipped and recorded with explicit reasons. Successful file results remain published even when other files fail.
- Address units are individual structured review comments dispatched through that same bounded worker scheduler. For each selected comment, Anne loads `INIT.md`, derives the current feature-spec heading shape from it once per run, builds a prompt with the source-comment metadata plus review patch context, trims the final assistant text, rejects empty output, rejects non-empty output that has no line whose first non-whitespace character is `#`, then normalizes accepted specs by inserting `## Source Comment` when absent and ensuring a trailing newline.
- Agent runtime configuration lives in `.anne/config.toml` under `[agent]` and `[review]`. `[agent].workers` limits concurrent per-file/per-comment agent invocations, defaults to `4`, and setting it to `1` restores serial fan-out. The shared runtime writes the prompt to agent stdin, preserves raw agent stdout as an artifact even on agent or filter failure, and optionally pipes stdout through `progress_filter` to obtain the final assistant text for either review JSON findings or address markdown specs.
- Agent responses must be JSON arrays of findings with `path`, `side`, `line`, `severity`, `title`, and `body`. Anne validates every anchor against changed old/new lines before publishing findings.
- Findings themselves do not make the command fail in v1. Operational problems such as repository/ref resolution failures, agent failures, invalid JSON, or invalid anchors mark the run failed while preserving the bundle for audit/debugging.
- `address` fails before bundle creation when no review outputs exist, `INIT.md` is unreadable, or a requested comment id is unknown. After bundle creation, per-comment agent failures or unusable outputs are recorded in the manifest and summary while later comments continue to run; the command exits non-zero if any selected comment failed.
- Automated coverage exists for CLI parsing, hunk-anchor parsing, merge-base review behavior, plain-text agent execution, progress-filter execution with invalid-anchor failure handling, rename-only review skipping from real `git2` diff data, bounded parallel review ordering and partial-failure preservation, newest-review address selection, lexicographic fallback selection for address, bounded parallel address ordering, empty address selections, partial-failure address artifact preservation, persisted-versus-rendered source-comment anchor handling across review and address bundles, serial fallback via `workers = 1`, and a guard test that blocks reintroduced Git CLI subprocess usage in tracked code and scripts.
