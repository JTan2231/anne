# Running Snapshot

Narrative theme
- Anne is now a filesystem-native diff review and follow-up planning CLI. The `review` command compares branches with merge-base semantics and persists findings under `.anne/reviews/`, while `address` turns persisted review comments into durable feature-spec bundles under `.anne/address/`.
- The repository also carries adjacent `.vizier` workflow templates for drafting, approving, and merging implementation plans, with durable plan-state records under `.vizier/state/plans/`.

Code state (behaviors that matter)
- `anne review --base <base> --head <head>` and `anne review <base>...<head>` both normalize to triple-dot review semantics. The command resolves the merge base between the two refs through `git2`/`libgit2` and reviews the diff from that merge base to `<head>`.
- `anne address` selects the newest usable review bundle at runtime from `.anne/reviews/`, preferring the newest recorded `generated_at` and falling back to lexicographic review-id order when timestamps are missing or tied. Address scans newest-to-oldest until it finds a bundle whose `comments.json` is readable and parseable, skips newer incomplete bundles quietly, and still treats bundles with `manifest.status = failed` as eligible when their comment snapshot is usable. `anne address <comment-id>` scopes that selected usable review bundle down to one comment.
- Each address run reserves a fresh `.anne/address/<address-id>/` root before writing run artifacts. The readable base id remains `<timestamp>-latest-<selection-filter-slug>`, and collisions retry deterministically as `-2`, `-3`, and so on, so same-second runs with the same logical filter stay isolated. Within that reserved bundle Anne writes `manifest.json`, `summary.md`, `selected_comments.json`, per-comment prompt/response artifacts under `agent/`, and generated markdown specs under `specs/`. `selected_comments.json` stays a sorted copy of the selected raw review comment objects, while prompts, summaries, and generated specs render readable `<side>:<line>` anchors on demand instead of persisting a separate `anchor` field. Empty review selections still produce a successful bundle with zero counts, and non-empty selections keep manifest/summary ordering stable by comment id even when worker completion order differs.
- `anne review` now has a bundle-less setup boundary before repo discovery/config loading only. Once Anne is in a discovered repo with a loaded config, it allocates a merge-base-independent review id, materializes `.anne/reviews/<review-id>/`, writes an initial `manifest.json` with `stage = preflight`, and then performs repository-open, ref-resolution, merge-base, and diff preflight inside that durable bundle.
- Review manifests now track `stage` (`preflight`, `file_review`, `rendered`) plus a machine-readable `preflight` progress object. `merge_base` and `diff_patch` stay nullable until those values are actually resolved/written, `files` stays empty until file enumeration starts, and preflight failures keep counts at zero while recording the terminating operational error.
- Successful review runs still write `.anne/reviews/<review-id>/manifest.json`, `diff.patch`, `comments.md`, `comments.json`, per-file patch artifacts under `files/`, and raw prompt/response artifacts under `agent/`. Preflight failures now persist a smaller terminal bundle with `manifest.json`, `comments.json = []`, and a readable `comments.md` that explicitly says no file review occurred; `diff.patch`, `files/`, and `agent/` remain absent until later stages.
- Review units are individual changed text files dispatched through a shared bounded worker scheduler. Binary diffs, pure rename-only changes, metadata-only changes, ignored prefixes from `.anne/config.toml`, and oversized per-file patches are skipped and recorded with explicit reasons. Successful file results remain published even when other files fail.
- Address units are individual structured review comments dispatched through that same bounded worker scheduler. For each selected comment, Anne loads `INIT.md`, derives the current feature-spec heading shape from it once per run, builds a prompt with the source-comment metadata plus review patch context, trims the final assistant text, rejects empty output, rejects non-empty output that has no line whose first non-whitespace character is `#`, then normalizes accepted specs by inserting `## Source Comment` when absent and ensuring a trailing newline.
- Agent runtime configuration lives in `.anne/config.toml` under `[agent]` and `[review]`. `[agent].workers` limits concurrent per-file/per-comment agent invocations, defaults to `4`, and setting it to `1` restores serial fan-out. The shared Rust runtime writes the prompt bytes directly to agent stdin, preserves raw agent stdout as an artifact even on agent or filter failure, and optionally pipes stdout through `progress_filter` to obtain the final assistant text for either review JSON findings or address markdown specs. Anne now treats `agent.output = "wrapped-json"` as a real runtime contract: when no filter result is available, Anne recovers the final `agent_message` text directly from the raw JSONL stream instead of treating wrapped output as plain text. Bundled-default provenance is tracked separately from explicit user config, so auto-selected `default/agent.sh` implies effective `wrapped-json` output even when no filter runs, while `default/filter.sh` is auto-selected only alongside the bundled default agent and only runs when `jq` is available on the child `PATH`. When that bundled filter renders generic `item.started` or `item.completed` events outside its specialized handlers, it now derives one shared fallback summary from `item.text`, then `item.message`, then `item.status`, so warning-bearing `item.type = "error"` payloads remain readable in stderr progress and can supply stdout fallback text when no later `agent_message` arrives. The bundled filter also treats wrapped-json `turn.failed` as a first-class stderr failure event, preferring collapsed `error.message`, then top-level `message`, then `detail` or `path`, so failed review/address runs preserve the concrete cause instead of only `event: turn.failed`. If `jq` is missing, Anne skips only that bundled filter, emits one degraded-mode notice, still succeeds, and records the effective runtime plus skip reason in review/address manifests and summary material. The bundled `default` shell shim still stages stdin losslessly before previewing the first line on stderr and forwarding the exact staged bytes into `codex exec --json -`, so recorded `agent/*.prompt.md` review artifacts stay byte-identical to what Codex received, including trailing newlines.
- Agent responses must be JSON arrays of findings with `path`, `side`, `line`, `severity`, `title`, and `body`. Anne validates every anchor against changed old/new lines before publishing findings.
- Findings themselves do not make the command fail in v1. Repository discovery still exits non-zero without a `Review bundle:` line, while repository-open, ref-resolution, merge-base, and diff-generation failures inside a discovered repo now exit non-zero with a persisted preflight bundle; agent failures, invalid JSON, invalid anchors, and later write failures after file-review materialization still mark the run failed while preserving the bundle for audit/debugging.
- `address` still has a pre-bundle validation boundary. It fails before bundle creation when no review outputs exist, `INIT.md` is unreadable, a requested comment id is unknown inside the selected usable review bundle, review bundles exist but none contain a usable `comments.json`, or a non-empty selection has no configured `agent.command`. After bundle reservation, per-comment agent failures, unusable outputs, and later write failures stay attached to that reserved bundle while later comments continue to run when possible; the command exits non-zero if any selected comment failed or a post-reservation persistence step failed.
- Anne’s default Cargo graph now keeps `git2` on a local-only surface by disabling the crate’s default `https`/`ssh` transport features and retaining only vendored `libgit2`. The checked-in Unix-like build contract is documented in `BUILD.md`: Rust `1.85+` plus a native C toolchain are required, while a system `git`, OpenSSL headers, libssh2 headers, and system `libgit2` are not part of the default path. `ci.sh` is now the canonical verification entrypoint and fails if `openssl-sys`, `libssh2-sys`, or the forbidden `git2` transport features reappear before running `cargo build --locked` and `cargo test --locked`.
- The checked-in `.vizier` draft workflow now treats a non-empty `spec_file` as file-backed plan provenance, rejects contradictory `spec_file`/`spec_source` tuples before prompt resolution, keeps prompt assembly grounded in `.vizier/prompts/DRAFT_PROMPTS.md`, and rewrites persisted plan-state records after `plan.persist` so file-backed plans carry `source = "file"` plus repo-relative `source_path`, text-only `inline`/`stdin` inputs persist as `source = "inline"`, and `summary` is normalized from the saved implementation plan doc by preferring `## Overview` prose before falling back to later plan/spec text or a deterministic `Plan <slug>` fallback. Approve/merge continue to consume the same plan artifacts without rewriting provenance.
- Legacy `.vizier/state/plans/*.json` records that predate `source_path` remain readable as incomplete provenance. The checked-in rollout policy is to backfill only audited records with authoritative originating-spec evidence and leave other legacy records unchanged.
- Automated coverage exists for CLI parsing, hunk-anchor parsing, merge-base review behavior, plain-text agent execution, persisted preflight bad-ref and merge-base failures, outside-repo review failure without bundle creation, progress-filter execution with invalid-anchor failure handling, bundled-default wrapped-json fallback when `jq` is missing, explicit custom-filter dependency failure preservation, wrapped-json protocol failure preservation, rename-only review skipping from real `git2` diff data, bounded parallel review ordering and partial-failure preservation, preserved bundle-path reporting on materialized output-write failure, newest-usable address selection including fallback past missing or invalid `comments.json`, lexicographic fallback selection for address, same-second address bundle collision suffixing, bounded parallel address ordering, empty address selections, partial-failure address artifact preservation, wrapped-json address-spec extraction without a shell filter, persisted-versus-rendered source-comment anchor handling across review and address bundles, serial fallback via `workers = 1`, a guard test that discovers tracked `src/**/*.rs`, tracked `tests/**/*.rs`, and tracked `*.sh` files from the repository index and blocks reintroduced Git CLI subprocess usage in that tracked code and shell-script surface, and dependency-surface guard tests that shell out to `cargo tree` and fail if Anne’s default graph regains `git2` remote-transport features or native remote-transport crates.
