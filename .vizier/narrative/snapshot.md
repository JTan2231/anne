# Running Snapshot

Narrative theme
- Anne is now a filesystem-native diff review and follow-up planning CLI. The `review` command compares branches with merge-base semantics and persists findings under `.anne/reviews/`, while `address` turns persisted review comments into durable feature-spec bundles under `.anne/address/`.
- The repository also carries adjacent `.vizier` workflow templates for drafting, approving, and merging implementation plans, with durable plan-state records under `.vizier/state/plans/`.

Code state (behaviors that matter)
- `anne review --base <base> --head <head>` and `anne review <base>...<head>` both normalize to triple-dot review semantics. The command resolves the merge base between the two refs through `git2`/`libgit2` and reviews the diff from that merge base to `<head>`.
- `anne address` selects the newest available review bundle at runtime from `.anne/reviews/`, preferring the newest recorded `generated_at` and falling back to lexicographic review-id order when timestamps are missing or tied. `anne address <comment-id>` scopes that same selected review bundle down to one comment.
- Each address run writes `.anne/address/<address-id>/manifest.json`, `summary.md`, `selected_comments.json`, per-comment prompt/response artifacts under `agent/`, and generated markdown specs under `specs/`. `selected_comments.json` stays a sorted copy of the selected raw review comment objects, while prompts, summaries, and generated specs render readable `<side>:<line>` anchors on demand instead of persisting a separate `anchor` field. Empty review selections still produce a successful bundle with zero counts, and non-empty selections keep manifest/summary ordering stable by comment id even when worker completion order differs.
- `anne review` has an explicit preflight/materialized boundary. Repository discovery, config loading, ref resolution, merge-base lookup, diff generation/splitting, and review-id construction happen before any `.anne/reviews/<review-id>/` path is guaranteed; once bundle creation starts, Anne reports that bundle path and preserves whatever artifacts were already written.
- Each materialized review run writes `.anne/reviews/<review-id>/manifest.json`, `diff.patch`, `comments.md`, `comments.json`, per-file patch artifacts under `files/`, and raw prompt/response artifacts under `agent/`. Final `comments.json` and `comments.md` are written only after all per-file results have been collected, globally sorted, and assigned deterministic `R001+` ids.
- Review units are individual changed text files dispatched through a shared bounded worker scheduler. Binary diffs, pure rename-only changes, metadata-only changes, ignored prefixes from `.anne/config.toml`, and oversized per-file patches are skipped and recorded with explicit reasons. Successful file results remain published even when other files fail.
- Address units are individual structured review comments dispatched through that same bounded worker scheduler. For each selected comment, Anne loads `INIT.md`, derives the current feature-spec heading shape from it once per run, builds a prompt with the source-comment metadata plus review patch context, trims the final assistant text, rejects empty output, rejects non-empty output that has no line whose first non-whitespace character is `#`, then normalizes accepted specs by inserting `## Source Comment` when absent and ensuring a trailing newline.
- Agent runtime configuration lives in `.anne/config.toml` under `[agent]` and `[review]`. `[agent].workers` limits concurrent per-file/per-comment agent invocations, defaults to `4`, and setting it to `1` restores serial fan-out. The shared runtime writes the prompt to agent stdin, preserves raw agent stdout as an artifact even on agent or filter failure, and optionally pipes stdout through `progress_filter` to obtain the final assistant text for either review JSON findings or address markdown specs.
- Agent responses must be JSON arrays of findings with `path`, `side`, `line`, `severity`, `title`, and `body`. Anne validates every anchor against changed old/new lines before publishing findings.
- Findings themselves do not make the command fail in v1. Preflight failures such as repository or ref resolution exit non-zero without a `Review bundle:` line, while agent failures, invalid JSON, invalid anchors, and later write failures after materialization mark the run failed while preserving the partial bundle for audit/debugging.
- `address` fails before bundle creation when no review outputs exist, `INIT.md` is unreadable, or a requested comment id is unknown. After bundle creation, per-comment agent failures or unusable outputs are recorded in the manifest and summary while later comments continue to run; the command exits non-zero if any selected comment failed.
- Anne’s default Cargo graph now keeps `git2` on a local-only surface by disabling the crate’s default `https`/`ssh` transport features and retaining only vendored `libgit2`. The checked-in Unix-like build contract is documented in `BUILD.md`: Rust `1.85+` plus a native C toolchain are required, while a system `git`, OpenSSL headers, libssh2 headers, and system `libgit2` are not part of the default path. `ci.sh` is now the canonical verification entrypoint and fails if `openssl-sys`, `libssh2-sys`, or the forbidden `git2` transport features reappear before running `cargo build --locked` and `cargo test --locked`.
- The checked-in `.vizier` draft workflow now treats a non-empty `spec_file` as file-backed plan provenance, rejects contradictory `spec_file`/`spec_source` tuples before prompt resolution, keeps prompt assembly grounded in `.vizier/prompts/DRAFT_PROMPTS.md`, and rewrites persisted plan-state records after `plan.persist` so file-backed plans carry `source = "file"` plus repo-relative `source_path`, text-only `inline`/`stdin` inputs persist as `source = "inline"`, and `summary` is normalized from the saved implementation plan doc by preferring `## Overview` prose before falling back to later plan/spec text or a deterministic `Plan <slug>` fallback. Approve/merge continue to consume the same plan artifacts without rewriting provenance.
- Legacy `.vizier/state/plans/*.json` records that predate `source_path` remain readable as incomplete provenance. The checked-in rollout policy is to backfill only audited records with authoritative originating-spec evidence and leave other legacy records unchanged.
- Automated coverage exists for CLI parsing, hunk-anchor parsing, merge-base review behavior, plain-text agent execution, preflight bad-ref failure without bundle creation, progress-filter execution with invalid-anchor failure handling, rename-only review skipping from real `git2` diff data, bounded parallel review ordering and partial-failure preservation, preserved bundle-path reporting on materialized output-write failure, newest-review address selection, lexicographic fallback selection for address, bounded parallel address ordering, empty address selections, partial-failure address artifact preservation, persisted-versus-rendered source-comment anchor handling across review and address bundles, serial fallback via `workers = 1`, a guard test that discovers tracked `src/**/*.rs`, tracked `tests/**/*.rs`, and tracked `*.sh` files from the repository index and blocks reintroduced Git CLI subprocess usage in that tracked code and shell-script surface, and dependency-surface guard tests that shell out to `cargo tree` and fail if Anne’s default graph regains `git2` remote-transport features or native remote-transport crates.
